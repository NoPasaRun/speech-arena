# Веселый трамбон — тестовая арена (Godot 4.3+)

Минимальный вертикальный срез: 3D-комната, подключение по IP (звезда
Client-Server-Client через ENet), персонаж от первого лица, тестовый
голосовой релей через сервер.

## Что нужно доделать руками в редакторе (не сериализуется надёжно текстом)

### 1. Input Map (Project → Project Settings → Input Map)
Добавь 4 действия и повесь клавиши:
- `move_forward` → W
- `move_back` → S
- `move_left` → A
- `move_right` → D

(`ui_accept` и `ui_cancel` уже есть в Godot по умолчанию — Space/Enter и Esc.)

### 2. Аудио-шина для микрофона (Audio панель внизу редактора)
1. Добавь новую шину, назови `Mic`.
2. На шину `Mic` добавь эффект **Capture**.
3. В Project Settings включи `Audio → Driver → Enable Input` (уже прописано
   в project.godot, но проверь, что галка стоит и в самом редакторе тоже).

### 3. MultiplayerSynchronizer на Player.tscn
Открой `scenes/Player.tscn`, выдели узел `MultiplayerSynchronizer`, вкладка
**Replication** → добавь свойства для синхронизации:
- `Player:position`
- `Player:rotation:y`
- `Player:Camera3D:rotation:x`

## Как проверить вдвоём на одной сети
1. Экспортируй/запусти проект на первом компьютере → "Создать комнату".
2. На втором компе — "Подключиться", в поле IP укажи локальный IP хоста
   (не 127.0.0.1, если это разные машины).
3. Оба должны видеть, как двигается персонаж друг друга, и слышать голос
   (после настройки шины Mic).

## Важные ограничения этой версии (осознанно, чтобы не тонуть в инфре)

- **Голос — не продакшен-решение.** Это сырой float32 PCM поверх ENet
  unreliable-канала: без Opus-сжатия, джиттер-буфера и эхоподавления.
  Годится проверить саму архитектуру "звезда через сервер", но для реальных
  зрителей (10+, нестабильная сеть на площадке) нужно переезжать на
  WebRTC + SFU (LiveKit или mediasoup) — как обсуждали.
- **Веб-экспорт не проверялся.** Если нужен вход "по ссылке в браузере",
  тестируй web-билд отдельно и заранее — там всплывают другие ограничения.
- **Роли зрителей (право говорить/громкость) не реализованы** — сейчас
  все, кто в комнате, шлют аудио на общих правах. Это следующий шаг:
  добавить в `players_info` флаг `can_speak`/`volume` и проверять его в
  `relay_audio` на сервере перед рассылкой.
- Файлы `.tscn` собраны вручную (не экспортированы из редактора) — если
  Godot откажется парсить какой-то узел, проще пересобрать именно его
  руками по структуре, описанной в файле, чем искать опечатку в тексте.

## Голос и реплики NPC (Яндекс SpeechKit + Claude Haiku)

Всё написано на GDScript, отдельного бэкенда нет: `scripts/AiBackend.gd`
ходит в API напрямую, `TurnManager.gd` гонит через него каждый ход
(STT → Claude Haiku → TTS голосом alena). Это выполняется только в процессе
сервера (см. «Запуск» ниже), клиент лишь проигрывает готовый
mp3, поэтому ключи нужны только серверу.

Ключи: скопируй `secrets.cfg.example` в `secrets.cfg` (в `.gitignore`) и
впиши `YANDEX_API_KEY` и `ANTHROPIC_API_KEY`, либо задай их переменными
окружения. Нет ключа — громкая ошибка при старте сервера.

### Ввод реплики

Два равноправных способа, итог всегда текст, который можно поправить:
- **клавиатура:** печатаешь в поле, Enter или «Отправить»;
- **голос:** «Говорить» открывает микрофон, текст в поле обновляется по мере
  распознавания (раз в 1,5 с сервер заново распознаёт накопленную запись),
  «Стоп» приносит итоговый текст. Настоящего потока нет: потоковый STT
  Яндекса — gRPC, из GDScript недоступен, а в API v1 стриминга нет.
  Каждое обновление — отдельный запрос к STT (тарифицируется по 15 секунд).

Когда отсчёт хода дошёл до нуля, отправляется то, что успели набрать. Если
после записи пишет, что речь не распознана, значит, до сервера дошла тишина
или мусор — проверь входное устройство в настройках ОС. Пока печатаешь,
WASD/пробел персонажа не двигают (см. `Player.gd`).

Запасных вариантов нет (ни espeak-ng, ни заготовленных реплик). Временные
сбои сети и 408/429/5xx запросы переживают повторами, а если шаг так и не
удался, ход честно проваливается: игрок видит причину и через пару секунд
повторяет ход.

### Запуск

Просто запусти игру (F5 в редакторе или собранный билд) — больше ничего не
нужно. `NetworkManager` сам поднимает сервер (`scripts/LocalServer.gd`):
это тот же проект, запущенный дочерним процессом `--headless --
--dedicated-server`, слушающим только `127.0.0.1`. Вывод сервера пишется в
`user://local_server.log` (путь печатается в консоль при старте — в консоли
редактора вывод дочернего процесса не виден). Сервер сам завершается, когда
игра закрыта; если клиентов нет 10 секунд после ухода последнего (или 2
минуты после старта, если никто не подключился) — тоже.

Расцепить на отдельные части (когда понадобится):
- клиент на чужой сервер: `--server=IP` (встроенный сервер тогда не
  запускается);
- сервер на отдельной машине: `godot --headless -- --dedicated-server`
  (без `--exit-when-idle` он работает постоянно, без `--bind=` слушает все
  интерфейсы). Ключи API нужны только ему.

Ограничения: встроенный сервер работает на десктопе (Windows/Linux/macOS);
на web и мобильных платформах он недоступен, там нужен внешний (`--server=`).
Яндекс не отдаёт CORS-заголовки, поэтому вызовы работают только из
нативного процесса (сервер), но не из web-экспорта.
